# Four more GitHub-reviewed Rust advisories missing from RustSec, and a yara-x fix that shipped in two steps (checked 2026-11-15)

By MV2 of Munim, Inc. (mv2@munimtech.com). Made with AI agents working in MV2's name.
Licence: CC BY 4.0. Every claim links to the public source it was read from.

`cargo audit` and `cargo deny` read [RustSec](https://rustsec.org), not GitHub's advisory database. We went
through the first three pages (75 entries) of
[GitHub's reviewed Rust advisories, newest first](https://github.com/advisories?query=type%3Areviewed+ecosystem%3Arust)
and checked each library crate against rustsec.org, the OSV record's aliases, and
[rustsec/advisory-db](https://github.com/rustsec/advisory-db) issues and pull requests.

None of the four crates has a RustSec page (rustsec.org/packages/&lt;crate&gt;.html returns 404), and no
advisory-db issue or pull request mentions
[smithy](https://github.com/rustsec/advisory-db/pulls?q=is%3Apr+smithy),
[xxhash](https://github.com/rustsec/advisory-db/pulls?q=is%3Apr+xxhash) or
[yara](https://github.com/rustsec/advisory-db/pulls?q=is%3Apr+yara).

- **aws-smithy-json**: the JSON parser that every smithy-rs generated deserializer calls skipped unknown keys
  by unbounded recursion; deep nesting overflows the stack (servers generated by smithy-rs are reachable by
  unauthenticated clients). Fix: [smithy-lang/smithy-rs#4685](https://github.com/smithy-lang/smithy-rs/pull/4685),
  which also bumps the crate to 0.62.7. AWS bulletin 2026-067-AWS.
- **aws-smithy-http-server**: the default `serve()` path had no working header read timeout (Slowloris-style
  DoS). The advisory links no commit; [smithy-lang/smithy-rs#4675](https://github.com/smithy-lang/smithy-rs/pull/4675)
  ("Add secure defaults", merged 2026-05-23, before 0.66.5 on 2026-06-01) turns on hyper's header read
  timeout and HTTP/2 keep-alive, and was matched by its description. AWS bulletin 2026-064-AWS.
- **xxhash-rust**: `xxh3_64_with_secret` and `xxh3_128_with_secret` checked the 136-byte minimum secret
  length only with `debug_assert!`, so release builds read out of bounds. Fix:
  [200cadb](https://github.com/DoumanAsh/xxhash-rust/commit/200cadb1a442c7f6cd9747e7d4297379b6b74200)
  adds `assert!` to both.

## yara-x: the advisory's "patched" version is incomplete

[GHSA-2jx3-ff3v-j7jj](https://github.com/VirusTotal/yara-x/security/advisories/GHSA-2jx3-ff3v-j7jj) (safe
`Rules::deserialize` accepts crafted compiled rules that later cause undefined behaviour) lists **1.19.0** as
patched, and so does GitHub's record. The 1.19.0 fix,
[25efa37](https://github.com/VirusTotal/yara-x/commit/25efa375572efcfbe880a263ee3b0932d4b61a24), checks only the
largest sub-pattern ID:

```rust
if rules.sub_patterns.len() < max_sub_pattern_id.0 as usize {
    return Err(SerializationError::InvalidFormat);
}
```

An ID equal to `sub_patterns.len()`, one past the last element, passes this check, and the scanner reads
sub-patterns with `get_unchecked`. Upstream later fixed this in
[9d6a1d8](https://github.com/VirusTotal/yara-x/commit/9d6a1d8930853dda39c8e582f4f64e5f2c87b0a2)
(2026-10-05, "improve robustness of deserialized rule data validation"). That commit checks every ID with a
strict `<`, adds a test for exactly the "off-by-one == sub_patterns.len()" case, and also checks anchored and
chained sub-pattern IDs, pattern IDs and code offsets. By the
[crates.io release dates](https://crates.io/crates/yara-x/versions) (1.21.0 on 2026-09-29, 1.22.0 on 2026-10-20),
**1.22.0 is the first release with the complete check; 1.19.0 to 1.21.0 still accept some crafted inputs.**
So MV2's RustSec draft uses `patched = [">= 1.22.0"]` and says why. This is upstream's own public fix, not a new
vulnerability; the point is that tools reading the advisory treat 1.19.0 to 1.21.0 as safe.

GHSA-h4wp) return 404 from OSV, meaning GitHub has not reviewed them, but RustSec already has them.

needs an alias-by-alias check), and application crates (mise, uv, hurl, mistralrs, fulgur), which RustSec
usually does not track.

## Limits

No exploit was run. The yara-x conclusion rests on reading the two commits and the release dates, not on
running crafted input against 1.19.0 to 1.21.0. The aws-smithy-http-server fix PR is our match; the advisory names
none. Download counts are crates.io "recent" (90-day) figures on 2026-11-15.
